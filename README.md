# PR Reviewer Assignment Service

Решение тестового задания: сервис для назначения ревьюверов Pull Request'ов. Написан на Go и PostgreSQL. Архитектура достаточно простая.

## Как запустить

### Через Docker Compose

1. В репозитории уже есть `docker-compose.yml`, который поднимает и API, и PostgreSQL.
2. Просто запускаешь:
   ```
   docker compose up --build
   ```

Сервис доступен по адресу `http://localhost:8080`.

## Остановка

```
docker compose down
```

Схема БД создаётся автоматически при старте приложения через goose миграции.

### Статистика

Добавил вспомогательный эндпоинт `GET /stats`, который возвращает:
- `reviewers` — сколько раз каждого пользователя назначали ревьювером;
- `pull_requests` — сколько ревьюверов у каждого PR.

### Линтер

Я использовал `golangci-lint`. Нужно поставить его локально (`brew install golangci-lint`). Для проверки достаточно запустить:
```
make lint
```
Конфигурация лежит в `.golangci.yml`, там оставил только базовые линтеры (`govet`, `staticcheck`, `unused`).

### Нагрузочное тестирование

Для проверки времени ответа и RPS прогнал `hey` по безопасному эндпоинту `/health`.

```
~/go/bin/hey -z 15s -c 10 http://localhost:8080/health
```

Что получилось:
- Средняя задержка ~ 1.0 ms, p95 ~ 1.8 ms.
- Средний запрос/секунда ~ 10.2k.
- Все 153k ответов вернулись с кодом `200`.

Тест запускал на личном ноутбуке с запущенным через Docker Compose сервисом. Ресурсов хватило, CPU заметно не проседал, так что считаю результаты достаточными для данного тестового стенда.

### Массовая деактивация пользователей команды

Добавил эндпоинт `POST /team/deactivate` для массовой деактивации всех активных пользователей команды с автоматическим переназначением ревьюверов в открытых PR.

**Функционал:**
- Деактивирует всех активных пользователей указанной команды
- Находит все открытые PR, где деактивированные пользователи были назначены ревьюверами
- Автоматически переназначает ревьюверов на активных пользователей из той же команды деактивированного ревьювера
- Если кандидата для замены нет, ревьювер просто удаляется из PR

**Пример использования:**

Запрос:
```
POST /team/deactivate
Content-Type: application/json

{"team_name": "backend"}
```

Ответ:
```json
{
  "team_name": "backend",
  "deactivated_users": ["u2", "u3"],
  "reassigned_prs": 2
}
```

**Производительность:**
Оптимизировано для средних объёмов данных (до 20 команд, до 200 пользователей), время выполнения < 100 мс.

### Интеграционные тесты

Добавил интеграционные тесты для repository слоя. Тесты проверяют работу с PostgreSQL базой данных.

**Запуск тестов:**
```bash
make test
```

**Что тестируется:**
- Создание команды с пользователями
- Массовая деактивация пользователей команды
- Создание и merge PR

Перед запуском тестов убедись, что PostgreSQL доступен на `localhost:5432` (можешь использовать `docker compose up db`).

## Вопросы и проблемы и как я их решал

1. **Хотел проверять reassign, но в командах не хватало активных ревьюверов.**  
   Сначала включил дополнительных людей через `/users/setIsActive`, позже добавил новых пользователей. После этого `reassign` заработал, потому что в команде появились кандидаты.

2. **Проверка бизнес ограничений.**
   В Postman сделал набор запросов (`create`, `merge`, `reassign`, `getReview`), чтобы руками убедиться, что:
   - PR создаётся и автоматически назначает до двух ревьюверов;
   - `merge` идемпотентен;
   - `reassign` запрещён после merge или если пользователь не назначен;
   - пользователю не выдаются PR, если его нет в системе.

3. **Падал линтер.**  
   Линтер падал из‑за того, что `golangci-lint 2.6` требует явного `version` в конфиге. Добавил `.golangci.yml` с `version: 2`, базовыми линтерами (`govet`, `staticcheck`, `unused`) и отключил `errcheck`.

4. **Оптимизация запроса для получения открытых PR с ревьюверами.**  
   Изначально делал отдельный запрос для каждого PR, чтобы получить список ревьюверов. Это было медленно при большом количестве PR. Переделал на один запрос с `array_agg`, который загружает все ревьюверы сразу. По итогу улучшилась производительность и получилось уложиться в требуемые 100 мс.

5. **Переназначение ревьюверов из правильной команды.**  
   Сначала искал замену в команде автора PR, но по заданию нужно искать в команде деактивированного ревьювера. Исправил логику и теперь для каждого деактивированного ревьювера получаю его команду и ищу замену именно там.
